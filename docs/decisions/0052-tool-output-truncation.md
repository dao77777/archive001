# 决策:工具输出上限由 `tool-executor` 统一截断

> 已接受 · 2026-10-24 · 落点 `packages/agent/src/loop/tool-executor.ts` ·
> **"截断放在 `executeBatch`、只留头部"已被 [`0054`](0054-tool-output-head-and-tail.md) 取代**
> (截断收进 `runTool`,头尾都留)
> 设计见 [`../designs/agent/loop.md`](../designs/agent/loop.md#工具)

## 矛盾

`TOOL_MAX_OUTPUT` 以前是**每个工具自己**调 `truncate(x, TOOL_MAX_OUTPUT)`:

| 问题           | 说明                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| 默认不安全     | 上限只对内置工具生效。`makeTool` 自造的工具、调用方传进来的任何 `Tool`,都可以无限输出 |
| 上限散在多处   | `bash` / `read_file` / `list_dir` 各写一遍,新增内置工具就得记住再写一遍               |
| 工具管了两次事 | 工具负责"产生观测"和"控制观测多大",后者是回喂前的一道闸,属于执行链而不是工具本身      |
| 换上限要改工具 | 想让某次会话收得更紧,得改工具或包一层;而工具是调用方给的、可能来自别的包              |

## 处理

截断挪到 `tool-executor` 的唯一出口:工具返回什么就喂什么,执行器在写回 inbox 之前截一次。

```ts
// tool-executor.ts
const output = truncate(yield * runTool(batch.tools, call.name, call.arguments), TOOL_MAX_OUTPUT);
```

连带改动:

- `builtin-tools.ts` 去掉三处 `truncate(..., TOOL_MAX_OUTPUT)` 与 `truncate` import(`bash` 只拼
  stdout / stderr / exit code,`read_file` 直接返回文件内容,`list_dir` 直接拼列表);
- `_constants.ts` 的 `TOOL_MAX_OUTPUT` 注释改成"单条工具输出回喂给模型的字符上限(`tool-executor` 统一截断)";
- `_domain.ts` 的 `Tool` 文档补一句"输出不必自己截断"。

## 为什么

- **默认安全**:不管工具从哪来,回喂给模型的观测都有上限;不需要每个工具作者记得这件事;
- **一个上限,一处实现**:截断率、后缀文案、边界都只有一处会错;
- **职责归位**:工具产观测,执行器管"观测怎么回到模型"(顺序、截断、写回 inbox 都是它的事);
- **上限可换**:以后想让上限按会话配,改执行器一处(或给 `ToolBatch` 加一个值),不动工具。

## 代价

- **工具失去对自身输出的控制**:想把"错误摘要"留在被截断的输出尾部的工具做不到 ——
  截断按字符切,尾巴一刀切掉;
- **后缀也可能被吃掉**:`bash` 的 `(exit code N)` 现在在待截断的字符串里,输出超长时它跟着被切;
- **上限对所有人一样**:某个工具确实需要长输出(比如返回完整文件)时没有逃生口,
  只能在工具里自己先压缩,或者以后给 `Tool` 加上限覆盖;
- **截断理由不显式**:模型看到"...[已截断,共 N 字符]"知道被截了,但不知道是工具截的还是执行器截的
  (现在统一是执行器;工具若自己截,会出现两层后缀)。

## 复查条件

1. **某个工具必须输出长文本**(整文件、完整 diff):给 `Tool` 加可选的输出上限或"分段读取"工具,
   而不是在执行器里开特例;开了特例就在本条追加 supersede。
2. **截断把有用信息切掉**(错误摘要、exit code 在尾部):改成"头部 + 尾部"保留,或让工具返回
   结构化观测由执行器序列化后再截断 —— 后者要先定义观测形状,别急着做。
3. **上限需要按会话 / 按工具配**:把 `TOOL_MAX_OUTPUT` 从常量挪到 `ToolBatch` 或 `AgentConfig`,
   执行器仍只做一次截断。
4. **出现第二种"回喂前处理"**(redact 密钥、压缩空白):和执行器截断放同一处,别散回工具里。
