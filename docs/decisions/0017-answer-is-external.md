# 决策:事件不判断"答案",由外部从 step 内容自己算

> 已接受 · 2026-10-24 · 取代 [`0016`](0016-flat-events.md) 里的 `answer.produced` ·
> 落点 `packages/agent/src/loop/` · 设计见 [`../designs/agent/loop.md`](../designs/agent/loop.md)

## 矛盾

0016 为了区分"工具调用前的宣告"和"最终回答",加了一个 turn 级内容事件

```ts
{
  _tag: ("answer.produced", turnId, text);
}
```

但这是**内核替外部做判断**:

| 问题                            | 说明                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| 事件应该是事实,不是解释         | `text` 是模型产出的正文;"它是不是最终答案"取决于这一步有没有 tool call,是投影层面的判断 |
| 内核不掌握所有客户端语义        | CLI 可能想要最后一步的 text;UI 可能想显示所有 text;记录/归档只想保留事实                |
| 空回答 / 多段 text 的规则被写死 | 一旦内核定义了 answer,外部再想换规则就得改事件                                          |
| 多一条特殊事件                  | 与"step 只含 thinking / text / tool.call"的简洁模型冲突                                 |

## 处理

- 删除 `answer.produced`。
- `text` 就是这一步模型产出的正文(可能多段),**属于 step**。
- 外部自己判断回答:
  - 一个 step 如果没有 `tool.call`,它的 `text` 就是这一轮的回答;
  - 实现上更简单:每遇到 `step.start` 清空缓冲,把 `text` 追加进去;到 `turn.end` 时,
    缓冲区里就是最后一步的正文(工具步的宣告会被下一步的清空覆盖)。
- CLI / REPL 渲染器:缓冲每步 text,遇到 `tool.call` 才把它作为"宣告"打印;
  最后一步没有 tool call,它的 text 由 `runTurn` 返回后统一打印,避免重复。
- Web 宿主:同样缓冲每步 text;tool call 步的宣告照常转发,最后一步的 text 不转发,
  由终止行 `{_tag:"answer"}` 统一给浏览器,避免 UI 重复渲染。
- `turn.end` 仍然只表示"这一轮结束了",`reason` 说明是正常结束 / 错误 / 中断。

## 为什么

- **事实与解释分开**:事件记录"模型说了什么";"这是不是答案"是外部根据 step 结构做的投影。
- **规则可替换**:将来想做"最后两步的 text 都算回答""只取最后一段""把回答交给另一个模型判定",
  都不需要改内核事件。
- **step 更纯**:一个 step 只有 thinking / text / tool.call,没有 turn 级的特殊内容混进来。
- **空回答天然可表达**:最后一步没有 text,回答就是空;不需要额外的"空 answer"约定。

## 代价

- **每个客户端都要实现同一段折叠**:step 边界 + text 缓冲;CLI / REPL / web 各有一份。
- **渲染容易重复**:如果客户端既渲染 text 又打印 `runTurn` 的返回值,最后一步会出现两次;
  CLI / REPL 用"缓冲 + 只在 tool.call 时打印"规避,web 宿主用"最后一步不转发 text"规避。
- **`text` 的语义依赖上下文**:单看一条 text 事件无法知道它是不是回答,必须结合 step 结构。
- **web 的 NDJSON 流不再包含最后一步的 text**:它被终止行 `answer` 替代;要完整重放应以 SDK 事件为准。

## 复查条件

1. **多个客户端反复算错回答**:抽一个客户端共享的纯函数 `answerOf(events, promptId)`(不是事件);
   内核仍然不判断。
2. **需要"每段 text 都可独立渲染"**:让 UI 自己按 step 折叠;不要为了 UI 方便恢复 `answer.produced`。
3. **回答规则变化**(例如多步总结):只改外部折叠函数;如果发现所有客户端都要同一套复杂规则,
   再考虑把它做成 SDK 里的纯投影助手。
4. **web 的"最后一步 text 不转发"造成重放缺口**:改成转发全部事件 + 浏览器端折叠;
   这只是客户端实现选择,不影响事件 schema。
