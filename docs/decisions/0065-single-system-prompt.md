# 决策:system prompt 只留一条,取消"没有工具"那套

> 已接受 · 2026-10-24 · 取代 [`0011`](0011-minimal-system-prompt.md) 的"有工具 / 没工具两套" ·
> 落点 `packages/agent/src/loop/_constants.ts`(后来这条常量随语义统一改名为 `SYSTEM_MESSAGE`)·
> 设计见 [`../designs/agent/loop.md`](../designs/agent/loop.md)

## 矛盾

`0011` 把 system prompt 收成两套:

```ts
const RULES_WITH_TOOLS = `不要执行破坏性命令(删除、覆盖用户数据),除非用户明确要求。`;
const RULES_WITHOUT_TOOLS = `本次没有任何工具可用:…;不要输出 <tool_call> …`;
export const systemPromptFor = (hasTools: boolean) => (hasTools ? … : …);
```

留着没工具那一套的**唯一理由**是一次实测事故:工具集为空时模型把调用写成正文
(`<tool_call>{"name":"shell",…}</tool_call>`),客户端既不执行也不继续。但它带来的代价是:

| 问题             | 说明                                                               |
| ---------------- | ------------------------------------------------------------------ |
| 两种提示词       | 同一个引擎有两套行为,讨论 / 测试 / 排查都要问"这次是哪一套"        |
| 引擎里多一个分支 | `systemPromptFor(definitions.length > 0)`,而这个判断只影响一段文案 |
| 文本会撒谎       | 没有工具时的提示词在"解释环境",而不是约束行为;它随工具集变化而变化 |
| 事故是概率性的   | 那次事故是模型行为,写一段禁令只是降低概率,并不能保证               |

## 处理

只留一条常量,引擎不再按工具集分支:

```ts
/**
 * system prompt 只放**不能从请求的 `tools` 字段推出来**的东西:一条安全约束。
 * 工具的名字 / 描述 / 参数已经在 `tools` 里,这里不重复。
 */
export const SYSTEM_MESSAGE = `不要执行破坏性命令(删除、覆盖用户数据),除非用户明确要求。`;
```

- `engine.ts`:发 `SYSTEM_MESSAGE` 事件与拼 `items` 都直接用这条常量(没有中转变量)
- 测试:两条"提示词跟着工具集走"并成一条 —— 断言 `system === [SYSTEM_MESSAGE]`、不含工具名、
  `tools` 字段照常带工具定义。

## 为什么

- **一个引擎一种行为**:提示词是引擎的常量,不随本次工具集变形;
- **少一个分支**:`systemPromptFor` 与其判断从引擎里消失,调用点不用想"这次有没有工具";
- **不解释环境**:system 只写约束;工具的可调用性由请求的 `tools` 字段表达(为空就是没有);
- **事故靠行为收敛**:那次事故属于"模型想调却没有工具",真正的兜底是客户端 / 引擎的执行语义,
  不是一段提示词。

## 代价

- **回归风险**:工具集为空时,模型可能再次把 `<tool_call>` 写进正文(web 宿主就是 `tools: []`);
  没有提示词兜底后只能靠客户端渲染忽略、或后续在引擎层过滤;
- **少一条"环境说明"**:模型不再被明确告知"本次没有工具",极端情况下会声称要读文件 / 跑命令;
- **要改文案就得改常量**:以后想按场景微调 system prompt(比如按 wire、按档位),得重新引入
  "参数化提示词"的设计。

## 复查条件

1. **空工具场景又出现"假装调用"并被用户看到**:先做执行侧的兜底(客户端把 `<tool_call>` 当正文、
   或在 `llm` 层截断),再考虑是否恢复一条**不带工具名**的通用否定句;不要恢复两套提示词。
2. **不同 wire / 档位需要不同提示词**:把提示词改成"常量 + 少量可选句"的组合函数,
   并在决策里写清每条句子的触发条件。
3. **需要按会话定制 system prompt**(产品级人设):在 `AgentConfig` 上加 `systemPrompt?`,
   默认用这条常量;此时 `SYSTEM_MESSAGE` 退化成缺省值。
