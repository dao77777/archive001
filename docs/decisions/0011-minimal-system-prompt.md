# 决策:system prompt 只留 `tools` 字段推不出来的东西

> 已接受 · 2026-10-24 · 落点 `packages/agent/src/loop/_constants.ts` · 相关
> [`../designs/agent/loop.md`](../designs/agent/loop.md)
> · "有工具 / 没工具"两套已由 [`0065`](0065-single-system-prompt.md) 合并成一条常量。

## 矛盾

`systemPromptFor` 之前拼了三块:

```
人格 + "你可以调用这些工具:bash、read_file、…" + 行为规则
```

但工具的名字、描述、参数 Schema 已经通过请求的 `tools` 字段传给模型
(`responses.ts` / `chat-completions.ts` 都带 `tool_choice: "auto"`)。模型原生 function calling
靠那份定义决定能不能调、怎么填参数。system prompt 里的工具名列表是**第二份事实**,而且:

| 问题                | 说明                                                      |
| ------------------- | --------------------------------------------------------- |
| 重复                | 同一份工具名既在 `tools`、又在提示词里;工具一多就是噪声   |
| 漂移风险            | 两处若不同步,提示词会承诺模型实际没有的能力               |
| 人格 / 风格是软约束 | "你是 archive001…""用简洁中文"不是能力,也不该硬编码在内核 |

唯一不能删的是**工具集为空时的否认**:提示词没否认、`tools` 又为空,模型会把调用写成正文
(实测 `<tool_call>{"name":"shell",…}</tool_call>`),客户端既不执行也不继续。

## 处理

```ts
// 有工具:只剩一条安全约束
const RULES_WITH_TOOLS = `不要执行破坏性命令(删除、覆盖用户数据),除非用户明确要求。`;

// 没工具:明确否认 + 禁止伪装调用
const RULES_WITHOUT_TOOLS = `本次没有任何工具可用:只能基于对话里已有的信息回答;
不要输出 <tool_call> 或 {"name": …} 这类标记,也不要声称执行过命令或读过文件。`;

export const systemPromptFor = (hasTools: boolean): string =>
  hasTools ? RULES_WITH_TOOLS : RULES_WITHOUT_TOOLS;
```

- 删掉 `PERSONA`、工具名枚举、"先查后答 / 任务完成后简洁结论"这类行为提示;
- 参数从 `toolNames` 改成 `hasTools`:调用方不需要为了提示词去取名字;
- 测试补一条断言:有工具时 `system` 不含工具名,而 `llm.complete` 收到的 `tools` 里有 `bash` ——
  把"能力事实来自 `tools` 字段"钉住。

## 为什么

- **能力只有一个来源**:模型能做什么由 `tools` 决定;提示词只放"没有工具"这种反事实,
  以及无法从 Schema 推出的安全约束。
- **少一处漂移**:不再需要保证"提示词里的工具名 = 本次 tools";`systemPromptFor(hasTools)` 只有两个分支。
- **最简可检查**:提示词一屏能看完,想确认"有没有夸大能力"只需看两句话。
- **行为提示的收益不确定**:是否调用工具、用什么语言收尾,DeepSeek 的默认行为已经够用;
  真有偏差时再加一句,比默认背一段人格更可控。
- **真 key 冒烟(2026-10-24)**:最简提示词下,模型仍然先 `list_dir`、参数错了还自己改用 `"."`
  再调一次,并接着用 `find` 核对;两轮答案都正确。工具名字列表确实不是感知工具的必要条件。

## 代价

- **少了人格 / 风格约束**:回答可能不再自称 archive001,收尾风格由模型默认决定。
- **少了"提醒用工具"的拉力**:弱模型或长对话里可能更倾向于直接回答;需要用真 key 冒烟观察。
- **安全约束只剩一句**:`bash` 仍可执行破坏性命令,提示词不是沙箱;真正的边界仍靠"只在本机回环、
  无审批"这一现状(见 [`0006`](0006-web-local-host.md))。

## 复查条件

1. **冒烟里工具调用率明显下降 / 模型开始凭记忆回答**:先加回一句"需要事实时优先使用可用工具"
   (不枚举名字);仍不够再考虑恢复名字列表,并记录原因。
2. **需要稳定的人格 / 输出格式**:把 persona / style 做成会话配置(类似 `LlmSettings` 的可选项),
   不要塞回内核常量;那时 system prompt 由"配置 + 有无工具"拼。
3. **工具定义大到 `tools` 字段本身就够重**:更不应该复制进提示词;若模型选错工具,优先改
   `description`,而不是加 system prompt。
4. **出现新的"空工具却伪装调用"变体**:优先完善 `RULES_WITHOUT_TOOLS`,而不是恢复整套提示词。
