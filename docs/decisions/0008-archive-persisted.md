# 决策:archive 落盘,`reasoning` 与其它条目同等记录

> 已接受 · 2026-10-22 · **方案已撤回**(对应的设计与实施计划已删除,本条只作存档;原落点 `loop/archive.ts`)
> **推翻**原 `AGENTS.md` 里「不要持久化 `reasoning`」那条(那份文件现在只描述现状,不再罗列禁令)。

## 矛盾

当时的设计要的是"内核状态只有一份 append-only 日志,其余全是投影",
而旧规矩给 `reasoning` 开了唯一一个例外:**可以看见,但不许记下来**。

| 要求                 | 旧规矩下的冲突                                                            |
| -------------------- | ------------------------------------------------------------------------- |
| 所有状态可重建       | 例外字段不可重建:重放出来的会话少一块,`fold(entries) ≡ 现场` 不成立       |
| 一个条目一套保留策略 | `llm_responded` 里 `reasoning` 内存留、`items` 落盘:一个条目两种命运      |
| 出站即投影           | 要么 `eventsOf` 多吃一个"飞行上下文"参数,要么 `thinking` 单独走第二个写者 |
| 会话要跨进程续跑     | 只持久化一部分的"状态源"不是状态源                                        |

"不落盘"的原始理由成立:思维链可能含可被同门弱模型解码的推理,公开研究里 4.9% 的推理块泄露过密钥。
但那说的是**离开本机**。本项目的实际形态是单机、单人、本地进程。

## 处理

- `reasoning` 是 `llm_responded` 的普通字段,**与 `items` 一起落盘**、一起重放、一起被 diff;
- `eventsOf` 恢复成纯函数(不带 `mode`:`thinking` 在实时与重放里一视同仁);
- `AGENTS.md` 里的那条禁令已删,文件改成“现状说明”;“本机私有、不进公开渠道”的意思仍然成立,
  但它现在是**代价与复查条件**的一部分,而不是一条规矩;
- 文件侧加码:目录 `0700`、文件 `0600`、`.lock` 独占、崩溃恢复只许追加。

## 为什么

- **例外会让设计塌**:一个字段两套保留策略,是"以后总会有人顺手全落盘"的温床;
  与其留个例外,不如把风险集中到**文件**这一处,用权限和"不进公开渠道"管住。
- **可观测性是主要收益**:思维链是本项目唯一的"过程"证据,不落盘就永远只能现场看一次;
  记录后可以对比"同一个前缀,换了档位 / 改了提示词之后它怎么想"。
- **"状态源"不能有缺口**:要支持重启续跑,就必须能恢复成现场的同一状态,否则 `validate` 的
  `fold ≡ 缓存` 这条最有效的自检直接失效。
- **权限比剥离更可靠**:剩下唯一真实的泄露入口是"文件被同步 / 被提交 / 被贴出去",那两条禁令比
  "代码里少写一个字段"更容易守、也更容易查(`git check-ignore` / 文件权限一条命令)。

## 代价

- **磁盘上是明文**:思维链 + 工具 stdout(可能是 env dump / token)一起躺在本地文件里;
  泄露面从"内存"扩到"磁盘 / Time Machine 备份 / 云同步盘 / 误 `git add`"。
- **文件格式成了兼容性负担**:`Item` 任何变化都会连带改磁盘格式(`v` 只能加字段)。
- **删不掉**:用户可以删整个会话文件,但"删掉某一条消息"做不到(append-only 的固有代价)。
- **旧文档要跟**:`AGENTS.md`、[`../designs/agent/loop.md`](../designs/agent/loop.md)、`drafts/` 里三处相反的说法一并改。

## 复查条件

1. **archive 要放到云 / 多机 / 共享给他人**:立即恢复"落盘前剥离 `reasoning`"(字段留空 + `reasoningBytes` 数字),
   并把本条标为 superseded;
2. **要给会话做"分享 / 导出"**:先有 redact 管线(工具输出里的密钥),再谈导出;
3. **合规要求"删除某条消息"**:加 `redacted(seq)` 墓碍条目,并接受"字节可能删不干净"(append-only 的固有代价);
4. **`reasoning` 开始含厂商特有的不透明载荷**(签名 / 密文):那它就不再是"普通文本条目",
   需要重新设计回放载体(见 [`0005`](0005-deepseek-only.md) 复查条件 1)。
