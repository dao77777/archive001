# 决策:Web 客户端用本地宿主,浏览器只做渲染

> 已接受 · 2026-10-21 · 所属设计 [`../designs/client/web/host.md`](../designs/client/web/host.md) · 落点 `packages/client/web/src/host/`

## 矛盾

Web 客户端今天在浏览器里**直连 DeepSeek 且没有工具**(内置工具依赖 `node:fs` / `child_process`),
所以它读不了文件、跑不了命令;密钥还明文躺在 `localStorage` 里。

参照物 `~/Code/@deepseek-harness` 的做法是"浏览器当薄客户端 + 本地 Node 托管"——
它的 `apps/web` 只是 `vite build` 的产物,由 `dsh web` 在 Node 里 serve,并带 loopback/Origin 校验。

## 选项

|          | A. 本地宿主(**决定**)             | B. 浏览器直连 + 工具代理        | C. 桌面外壳              |
| -------- | --------------------------------- | ------------------------------- | ------------------------ |
| 循环在哪 | Node                              | 浏览器                          | Node(进程内)             |
| 工具     | 内置四件套直接用                  | 每次调用跨进程过一次代理        | 同 A                     |
| 密钥     | 只在宿主                          | 仍在浏览器                      | 同 A                     |
| 复杂度   | 中(1 个新入口)                    | 高(把 executeToolCall 拆成两半) | 高(打包 / 签名 / 三平台) |
| 复用现有 | `agent.run` + `BuiltinTools` 原样 | 要改循环                        | 同 A                     |

C 是 A 的超集,先有 A 再包桌面才有意义;B 会把"事件循环"切成两段,是最难维护的一种。

## 处理

1. `packages/client/web/src/host/` 新增宿主(HTTP + Vite 中间件 + `/api/{state,turn,reset}`),
   一个 `ManagedRuntime` 活到进程结束。
2. 浏览器侧 `use-agent.ts` 改成 `fetch("/api/turn")` 读 NDJSON;事件仍喂 `appendEvent`(渲染层零改动)。
3. 密钥从界面彻底移除:只从宿主环境读 `DEEPSEEK_API_KEY`(与 cli 一致)。
4. 安全四条:只绑回环、`Host` 校验、`Origin` 同源、一次性 `HttpOnly` cookie。
5. 工具**不做前端确认**(已定),因此宿主只允许跑在本机回环。

## 为什么

- **能力对得上**:工具、密钥、会话历史都在有能力的进程里,浏览器不需要任何特权。
- **安全是净收益**:密钥离开浏览器;同时把"本机端口"当成边界认真处理(不像纯前端那样无从防护)。
- **改动面小**:渲染层(`app.tsx` / `_util.ts` / 组件)**几乎没动**,只换掉了外呼那一层。

## 代价

- 部署形态从"静态站点"变成"本地常驻服务":页面不再是打开就能用。
- 会话在服务端,**刷新页面 ≠ 新会话**成为新事实;目前用"挂载时 `/api/reset`"把它拉回旧语义,
  代价是两个标签页会互相清掉历史。
- 工具有真实破坏力且没有确认流程:`bash` 在宿主 cwd 下能执行任何命令。UI 只显示目录,不做拦截。
- 宿主多一份 HTTP/校验代码(约 300 行,无框架依赖)。

## 复查条件

1. 若有人把宿主绑到 `0.0.0.0` 或去掉 `Origin` 校验 —— 这是安全回退,必须当 bug 修,不允许"临时方便"。
2. 若开始需要"多会话 / 历史持久化" —— 说明"一个进程一个会话"不够用,那时应引入会话 id,
   而不是靠多开进程。
3. 若需要"工具确认" —— 那么 B/C 的差距拉近,可重新评估;但只要还在本机回环、单人使用,A 仍最优。
