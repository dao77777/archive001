## Web 宿主压到三个文件

- **为什么**:`host/` 的 7 个文件里,`_constants` / `_domain` / `_util` 合计 128 行、只服务同一个目录;
  回答一个简单问题要跳三四个文件(请求会不会被拦?→ `main` → `guard` → `_util`)。
  `TOKEN_COOKIE` 一个字符串单独占一个文件,`guard.ts` 只有一个消费者还带着独立测试文件。
- **怎么改**:
  - `host/` 只剩 `main.ts`(常量 + 页面 + `HttpServer` + `launch`)、`api.ts`(常量 → 纯判定 → 安全闸 → 四条路由 + 404)、
    `session.ts`(服务 + `TurnEvent` / `SessionSummary` / `SessionShape`);
  - 删除 `_constants.ts` / `_domain.ts` / `_util.ts` / `guard.ts` / `routes.ts`;
  - `_util.test.ts` → `api.test.ts`,跟被测物走;`Guard` 仍由 `main.ts` 与页面层一起 merge(全局闸不变);
  - 请求体 Schema 就地写在路由旁;`session.ts` 的 `titleOf` 去掉重复的 `_tag` 判断;
  - 新增 `postJson(path, schema, handler)`:`HttpRouter.add` 的 handler 只拿到原始 request,body 形状得
    进函数里找 `schemaBodyJson(...)`;包一层以后 handler 第一参数就是解好的 body,413 也统一在助手挡。
    副作用:413 的判定从"密钥检查之后"提前到"之前"(缺密钥 + 超大 body 现在回 413)。
- **代价**:`api.ts` 207 行、`session.ts` 214 行,靠分区注释而非文件边界;`host/` 不再符合三件套约定
  (已在 `code-conventions.md` 注明例外);纯判定单测会连带加载 `@archive001/agent/live`(430ms,import 占 82%)。
- **验证**:`pnpm check` / `pnpm typecheck` / `pnpm test`(2 文件 9 用例,web 部分)全绿;重启宿主后实测
  `/api/state`(200 + 种 cookie)、`/api/sessions`、`/api/nope`(404)、无令牌 `/api/turn`(401)、
  外部 `Host`(401)、代理形态 `Host: localhost:5173`(200)、超大 body 声明(413)、空输入(400)、
  坏 body(`{"input":123}` → 400),以及三次真 `turn` 的 NDJSON 事件流(末行 `ANSWER` 分别为 `2` / `7` / `11`)。
- **后续(同日)**:框架件拆到 `host/framework.ts`(`postJson` / 响应 / `ndjson` / 安全判据 / `nodeServer` / `run`),
  `api.ts` 只留令牌策略、请求体 Schema 与四条路由;`api.test.ts` → `framework.test.ts`。
  文件从 3 个回到 4 个,但框架与业务之间是真实接缝(框架件与 archive001 无关),暂不抽成独立包。
- **再一轮(同日)**:去掉 `json = HttpServerResponse.jsonUnsafe` 这层别名,调用处直接
  `HttpServerResponse.jsonUnsafe`(少一层跳转,也顺带提醒它是"立即求值、stringify 失败即抛");
  错误定义**全部集中到 `framework.ts`** 的「错误」段(400 / 401 / 404 / 413 / 503 按状态码排,
  一律 thunk),`api.ts` 只用不定义 —— 只把 401 包一层 `withCookie`(握手)。
- **命名(同日)**:错误族全部大写 + `HTTP_ERR` 前缀 —— `HTTP_ERR_BAD_REQUEST` / `_UNAUTHORIZED` /
  `_NOT_FOUND` / `_TOO_LARGE` / `_SERVICE_UNAVAILABLE`;工厂 `HTTP_ERR(status, msg)` 内联掉,
  每条自己 `HttpServerResponse.jsonUnsafe({ error }, { status })`,**一律写成 thunk**(`HTTP_ERR_NOT_FOUND()`),
  这样"模块加载时算好、却随请求共享"那种隐式共用就没有了。

## 宿主改用 `effect/http-api`

- **为什么**:`postJson` 只覆盖"POST + JSON";`effect/http` 的每种来源各有一个解码器,按 0087 的路子走下去要
  为表单 / multipart / 路径参数 / query 各写一个助手,最后得到"http-api 的残缺私有版"。
- **怎么改**:
  - `api.ts` 改声明式:`HttpApiEndpoint.<method>(标识, 路径, { payload, success, error })` + `HttpApiBuilder.group(...).handle(...)`;
    handler 直接拿解好的 `payload`;
  - 响应 Schema:state / sessions / openSession / reset 用 `Schema.Struct`;`/api/turn` 用
    `HttpApiSchema.StreamUint8Array({ contentType: "application/x-ndjson; charset=utf-8" })`,handler 直接返回 `Stream<Uint8Array>`;
  - 业务错误:`HttpApiSchema.status(400|503)(Struct({ _tag, error }))` + `Effect.fail(...)`;
  - `RequireToken` 与 413 合进全局 `Guard`(按路径集合判令牌、按 `content-length` 判超限);
  - `framework.ts` 删掉 `postJson` / `ndjson` / 两条业务错误,只留 401 / 404 / 413、`encodeNdjsonLine`、安全判据与启动;
  - `main.ts` 多一层 `HttpApiBuilder.layer(Api).pipe(provide(ApiLive), provide(Etag.layer))`。
- **代价**:契约与实现分两处;错误体 400 / 503 多一个 `_tag`;`Schema` 解码失败变成空体 400;
  401 / 404 / 413 与端点错误分成两套;`cache-control: no-store` 消失。
- **验证**:`pnpm check` / `pnpm typecheck` / `pnpm test` 全绿;重启后实测
  `state` 200、`sessions` 200、`/api/nope` 404(`{"error":"not found"}`)、无令牌 turn/reset/open 全 401、
  外部 `Host` 401、代理形态 `Host: localhost:5173` 200、超大 body 413、空输入 400(`{"_tag":"BadRequest",…}`)、
  坏 body 400、`reset` 200;真 `turn`:**10 行 NDJSON、末行 `{"_tag":"ANSWER","text":"13"}`**、
  `content-type: application/x-ndjson; charset=utf-8`、`Transfer-Encoding: chunked`、响应仍带 `Set-Cookie`。
- **落档**:[`../decisions/0088-http-api-declarative.md`](../decisions/0088-http-api-declarative.md)、
  [`../designs/client/web/host.md`](../designs/client/web/host.md)、[`../README.md`](../README.md)。

## archive 按会话分文件

- **为什么**:所有条目挤在 `~/.local/state/archive001/archive.jsonl`,而路径是 `live.ts` 的常量、当参数传给
  `FileSinkLive` —— 调用方被迫知道"文件在哪";同时"单文件 + 单 writer"在多实例(多 agent / 子 agent)下
  会互踩。`sessionId` 早就在条目上,文件层面却没用。
- **怎么改**:
  - 路径下沉:`file.ts` 固定 `ARCHIVE_DIR = ~/.local/state/archive001/sessions`,`FileSinkLive` 不再收参数;
    `live.ts` 改成 `Layer.provide(FileSinkLive)`,删掉 `ARCHIVE_FILE` 常量与 `homedir` / `join` 依赖;
  - 写:`write` 按 `sessionId` 分组 → `<会话>.jsonl` 各自追加(每次 open→write→close,不攒 fd);
  - 文件名只留 `[A-Za-z0-9_-]`,被改过的补 8 位 sha256(挡 `../` 与 `a/b` vs `a_b` 撞名);
  - 读:老单文件(`sessions/` 的兄弟 `archive.jsonl`,只读不迁移)+ 目录下每个 `*.jsonl`,
    各自解析后按 `at` 稳定归并(`ArchiveRuntime` 用"最后一条"决定默认会话,不能按目录顺序凑);
  - `Sink` 契约不变:`read` / `write` 两个方法,调用方零改动。
- **代价**:跨会话顺序靠 `at` 重建(同毫秒极罕见的不确定);一批跨 k 个会话就开 k 次文件;
  异常 id 的文件名带哈希;老文件永久保留、`read` 多读一个文件。
- **验证**:`pnpm test` 101 用例(含 6 条 sink 用例:分文件、路径逃逸、跨会话按 at 归并、坏行截断、
  缺目录);`pnpm check` / `pnpm typecheck` 全绿。实际重启宿主后:
  老会话仍在(`legacy` 852 条、`54260498` 13 条、当前 `b6818317` 279 条 = 老文件 1144 行),
  跑一轮后新条目写进 `sessions/b6818317-….jsonl`(2403 字节),再重启计数变 292 且无重复。
- **同日再改(取消兼容)**:按要求不再兼容旧格式 —— 删掉 `LEGACY_SESSION_ID` 与"缺 `sessionId` 归到 legacy"的
  全部逻辑;sink 写缺 `sessionId` 的条目直接 `ArchiveError`(不猜文件)、投影收到无会话条目直接抛错;
  `read` 只读 `sessions/`;旧数据(`archive.jsonl` 224KB、`archives/` 两份、`sessions/` 两份)已删除。
  实测:重启后会话列表只剩一条空的新会话,`reset` + 一轮对话后目录里出现 `888c85f1-….jsonl`。
