## Web 底栏:状态栏压成一行

**起因**:底栏原来是两行 —— 上方 `model` / `thinking` 两个方框字段 + 方框按钮 `设置`,下方单独一行状态
(`готов · 就绪` 与 `ход 000`)。控件在三处重复"我是控件"(边框 + 底色 + 按钮外观),比读数更抢眼;
底栏高度也会随换行跳。

**改成**:一行,全部落在同一基线上,10–11px 等宽、`muted`、无框无底色。

| 位           | 前                         | 后                                      |
| ------------ | -------------------------- | --------------------------------------- |
| `model`      | 方框输入,固定 144px        | 裸字段,宽度 = 内容 +1ch(不截断也不多占) |
| `thinking`   | 方框下拉                   | 裸下拉,`▼` 降到 8px                     |
| `设置`       | 方框按钮 `.btn .btn-ghost` | 裸文字 `.bare-btn`,与读数同级           |
| 状态 / `ход` | 独占第二行                 | 同行右端,状态可截断,**不换行**          |

实现落在 `styles.css` 的 `.bare-input` / `.bare-btn`(边框透明,hover 灰底线、聚焦墨底线)
与 `controls.tsx` 的 `variant: "box" | "bare"`;骨架外的东西一个没动,方框 `.field` / `.btn` 仍给设置弹层用。

**代价**:无框控件少了"这里能点"的暗示,只能靠 hover 与光标;小屏靠截断状态文字保住一行。

**没做**:底栏上方那条发丝线保留 —— 它是归档框的收口,不属于状态栏;要去掉得连外框一起改。

## 删掉输入框上方那条分隔线

**结论**:**是多余的,已删。** 它和输入框自己的底线只隔 16px,等于把同一件事说了两遍
("这里是输入区");而且它是全页唯一一条横贯到底的线,读起来更像"页面下边框"。

**A/B 依据**(1280×820,同一份 8 轮示例消息):

| 版本           | 观感                                           |
| -------------- | ---------------------------------------------- |
| 有分隔线       | 底栏两线夹一条 16px 的空白,像被框起来的一栏    |
| 无分隔线(现用) | 消息流 → 留白 → 输入底线,层次没丢,底栏安静很多 |

底栏边界靠三样东西就够了:消息流自己的 `py-8`、footer 的 `pt-4`、输入框的底线。
顶栏下那条发丝线保留 —— 它是全页唯一横贯线,也是"纸"的上边界。

**代价**:滚动区的下边界不再有标记;真出现"文字被切一半"的观感(目前 `scroll-to-bottom`
下不会),用淡出遮罩解决,而不是加回线。

**复查条件**:若某天把输入区改成多行大框(上限 180px 那种)或加了附件区,底栏会长高,
那时需要重新引入一条边界 —— 但那时应该用色块(比纸面暗一档),不是横线。

## 模型 / 档位改成右下角的两个控件

**做了什么**

| 项     | 前                               | 后                                                  |
| ------ | -------------------------------- | --------------------------------------------------- |
| 位置   | 底栏左侧的脚注式小字             | **页面右下角**贴角(与左下状态同一基线)              |
| 标签   | `MODEL` / `THINKING` 两个说明词  | 删掉;靠 字色 / 字号 / 字距 / 大小写 / 可点形态 区分 |
| 模型   | 文本框,手打型号                  | **下拉选择**,只列已知型号(向上弹)                   |
| 档位   | 下拉选择                         | **点一下切换** off → low → high → max → off         |
| `设置` | 挤在同一行                       | 挪到顶栏,和「清空」并列                             |
| 持久化 | 已有 `useEffect` 写 localStorage | 保留,并首次做**真浏览器验证**(见下)                 |

对比区分(不写标签的代价就是这四条都得成立):

|             | 模型                 | 档位              |
| ----------- | -------------------- | ----------------- |
| 字色        | 墨                   | 灰                |
| 字号 / 字距 | 12px 常规            | 10px 疏排 `.18em` |
| 大小写      | 原样小写(是指标识符) | 大写              |
| 可点形态    | `▽` 下拉             | 无箭头,点即切     |

**为什么不手打型号**:写错的模型名不会在本地报错,只会在请求时变成 400 —— 让它在源头选不
出来更便宜。旧持久化里的未知型号不丢:原样保留并排在最前。

**持久化实测**(playwright-core 驱动本机 Edge,无头,临时 profile):
点档位两次 → `localStorage` 变 `thinking: high → max`;下拉换 `deepseek-v4-pro` → 写回;
`reload` 后读回 `deepseek-v4-pro / max`,DOM 与存储一致。也就是说 model / thinking 一直
是持久化的,这次只是把**输入方式**换成了选/切。

**代价**:① 控件离输入框远了(宽屏上在页面另一头),需要一次扫视;② 没有标签,第一次用要靠
hover 与 `title` 发现"这个 LOW 能点";③ 型号表是写死的常量(`_constants.ts` 的 `MODELS`),
厂商出新型号要改代码。

**复查条件**:如果不止一次有人问"档位在哪"或点不到切换,就把档位改成带箭头的循环按钮(形态
向模型看齐),而不是加回标签。

上一节把模型 / 档位钉到了**页面四角**(`absolute inset-x-10 bottom-7`),理解错了:要的是**输入框

**代价**:这条 caption 与输入底线只隔 8px,输入框长高到 180px 上限时仍贴着 —— 可接受;

## 动作下移、顶栏那道线删掉、占位符只讲输入

**1. 设置 / 清空搬到输入框下沿**

顶栏只剩"是什么":字标 + 密钥状态。动作跟状态一起放在输入框下沿右端:
`设置 清空` ｜ `deepseek-flash ▽` `LOW`。没 key 时 **`设置` 自己变红**(红只表示"需要你动手"),
所以顶栏的红字和它同屏时是同一条信息的两种位置,不再额外造提示。

**2. 顶栏下那条发丝线:删了**

理由:它唯一的实际功能是遮住滚动区顶边的"切半行",而这件事用淡出遮罩(`mask-image`)做得更好 ——
遮罩是渐隐,线是把切边藏到线下,前者在任何滚动位置都成立。删掉后**页面上一条横贯线都没有了**
(只剩输入底线、标签领线、工具块顶线,全都是有头有尾的短线)。

**3. 占位符只讲输入**

`先在设置里填 key` → `说点什么 · enter 发送 / shift+enter 换行`(不再随 key 状态变)。
占位符的职责是"这个框里写什么",不是"去别处干点什么";缺 key 由按钮变红 + 顶栏红字表达。

**代价**:① 空态说明文案里的"设置"指向从"顶栏"改成"下面",文案与位置耦合,以后搬按钮要改文案;
② 遮罩让滚动区顶部有 28px 渐隐,截图里看是"文字淡进纸里",如果哪天要打印式截图会显得不实。

**复查条件**:如果淡出遮罩在某些浏览器(旧 Safari)上不生效、切边重新露出来,再考虑给滚动区加
1px 顶线 —— 但那时应该只画到内容宽度(76ch),不横贯整页。

## 去掉「清空」、密钥状态挪到「设置」旁、设置不再红

| 项       | 前                    | 后                                                |
| -------- | --------------------- | ------------------------------------------------- |
| 清空     | 输入下沿的一个按钮    | **删掉**(连 `useAgent` 里没人用的 `reset` 一起删) |
| 密钥状态 | 顶栏右侧              | 输入下沿、紧挨「设置」                            |
| 设置     | 没 key 时整颗按钮变红 | 永远中性幽灵字;**红只给旁边的状态字**             |
| 顶栏     | 字标 + 密钥状态       | **只有字标 + 编号**                               |

**为什么删清空**:会话本来就不落盘,刷新即空 —— 这个按钮在做一件浏览器已经免费提供的事,
还多出一个能误触的破坏性操作。要开新卷,刷新。

**为什么状态紧挨设置、红不放在按钮上**:两个理由。① 位置:需要动手的地方旁边就该写着
为什么需要动手,而不是隔着整个屏幕(顶栏)去说;② 语义:红在本项目里只表示**状态**
(出错、未配置、正在发生),按钮是**动作**,动作不该占用红 —— 否则红就变成"重点按钮色",
和设计里"红从不铺面、只做标点"的规矩冲突。

**代价**:① 想重开会话的人第一次会找不到入口(得知道"刷新"就行);② 顶栏只剩字标,
右上角空着,页面更像一张纸 —— 接受。

**复查条件**:如果真出现"想留住某一卷、只想清空当前会话"的需求,再加回清空,但那时它应该是
输入下沿的一个**中性**幽灵字(和设置同级),不要做成红色。

删除后的核对:`useAgent` 不再返回 `reset`;`pnpm typecheck` / `pnpm check` 全绿;
浏览器实测 `设置` 仍能开弹层、页面里已没有"清空"这个词。

## 模型 + 档位:让它们看起来是一组

原来 `deepseek-flash ▽   LOW` 和左边的 `设置` 用同一个间距(32px),三个东西像一串并列项。
现在按"组"来排:

| 线索   | 做法                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| 近距   | 组内 12px,组外 40px —— 3 倍差,眼睛先按距离分块                                                   |
| 分隔符 | 组内插一根 1px × 14px 竖线(`bg-rule`),"一个整体里的两段"而不是"两个独立项"                       |
| 语义   | `deepseek-flash ▾` 是"用哪个模型",`LOW` 是"这个模型想多深" —— 后者修饰前者,所以是分隔符,不是句号 |
| 读屏   | `role="group"` + `aria-label="会话参数"`,视觉分组和语义分组对齐                                  |

**没用**的手段:加标签(前面已经删了)、给这组加边框或底色(会让 8px 之上的输入底线变成两条平行线)、
把两者做成完全同款(那就丢掉了"哪个是模型、哪个是档位"的对比)。

**代价**:分隔符在 420px 折行时跟着模型走,不拆开 —— 这正确;但折行后整组贴右,左端状态与它之间
只剩一行空白,层级靠的就是那 3 倍间距差。

**复查条件**:如果还有人问"这两个是一起的吗",下一个手段是共享悬停(**hover 其中任一,两者同时出现
1px 底线**),而不是加标签或加框。

## 分组只留间距;空态文案砍到两行

**1. 模型 / 档位:去掉竖分隔符**

上一版在两者之间嵌了一根 1px 竖线,用户判断"太抢眼"。去掉后分组**只用间距**:
组内 12px、组外 40px(与左边「未配置密钥 + 设置」那对用同一套规则:对内 12px,对外 40px)。
`role="group"` + `aria-label="会话参数"` 保留 —— 视觉上靠距离,语义上靠标签。

**2. 空态:三行变两行(没 key 时三行)**

| 前                                                                                                                     | 后                                                  |
| ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 开卷 / 卷宗 · 待归档 / 等待第一条记录                                                                                  | **启封** / 等待第一条记录                           |
| 两行说明:`在下面点「设置」填上 DeepSeek key 就能开始。` + `密钥存在这台浏览器的 localStorage 里;模型 / 档位也会记住。` | 没 key 时一句:`点下面的「设置」填入 key 即可开始。` |

砍掉的:重复的"卷宗 · 待归档"(与"等待第一条记录"同义)、`localStorage` 的解释(设置弹层里已经
写明存储位置与风险,不在这里说第二遍)。留下的:状态(启封 / 等待第一条记录)+ 唯一的行动入口。

用"启封"代替"开卷":启封是**档案/封套**的动作(拆封、开启密封),比"开卷"更贴档案的口气,
也更像一个状态而不是一句劝学。

**代价**:没 key 的人如果先读中心再看右下,可能先看到"启封"而不知要填 key —— 靠那句指路兜住;
配好 key 后这句话消失,空态只剩两行,页面更空。

**复查条件**:若第一次用的人仍然去输入框直接打字(而不是先点设置),就把那句指路改成动词在前的
短句(「先填 key,再开口」),而不是把说明段落搬回来。

## 去掉左上角的文本(字标 + 编号)

页面不再自报家门。`archive001` 与 `档案 001` 从左上角拿掉,顶栏整块删除;消息流的上内距
`pt-8 → pt-12`,让第一块内容离裁切标记远一点。

**名字去哪了**:① 浏览器标签页(`index.html` 的 `<title>archive001</title>`);② 空态右缘的竖排
`档案 001`。

**代价**:① 聊天进行中(空态消失)页面上**没有任何品牌字样**,只剩内容与两行标注 —— 这是有意的,
但换个人来看会不知道自己在用什么;② 白屏/首帧时更没有方向感(靠标签页标题兜);③ 空态竖排标签
在开始对话后就消失,身份信息是"有时出现"的。

**复查条件**:如果被人问"这是什么应用"超过一次,就把竖排 `档案 001` 从空态提到页面层(固定在
内容列右上,`pointer-events-none`),而不是把字标搬回左上角。

## 不再播报"密钥已配置"

状态行只报**问题**:"已配置"是常态,常态不需要占位。所以 `密钥已配置` 整个删掉,只在缺 key 时
显示红字 `未配置密钥`(仍紧挨「设置」)。

**实测**(真浏览器两态):无 key → `未配置密钥 设置 deepseek-flash low` + 空态那句指路;
有 key → `设置 deepseek-flash low`,DOM 里没有任何"密钥"字样。

**代价**:① 配好之后没有任何"已经生效"的确认 —— 判断依据变成"没有红字";② 首次填完 key 保存后,
页面唯一的反馈是那句指路消失 + 红字消失,若用户在弹层里没注意,可能不确定是否保存成功
(弹层里的"完成"关闭可算半个确认)。

**复查条件**:如果有过一次"填了 key 但不确定有没有生效"的困惑,再考虑让「设置」在保存成功的那一瞬间
闪一次(短暂变墨再回灰),而不是常驻一句"已配置"。

## 用户的话:黑底改成「登记条」

**为什么不能是黑底**:两个理由。① 设计里"暗场只留一个用途:思考中" —— 用户气泡也是黑块,
就把这条规矩打穿了;② 一整块墨色是页面上最重的东西,比主体(卷宗夹)和答复都重,层次是反的。

**改法**(不填充,用笔迹和位置说话):

| 线索 | 做法                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------- |
| 位置 | 右对齐(答复、工具、思维链都在左)                                                                      |
| 字面 | **等宽 12.5px**(答复是 14px 无衬线)—— 读作"你敲进登记簿的一条",和排好的正文是两种笔迹                 |
| 边线 | 右侧一根 **1px 墨线**(`border-r border-ink/40`),只有高度、没有围合;对应错误块的左侧 2px 红线,一左一右 |

试过并放弃的:细右边线 + 无衬线(和答复太像,分不出是谁在说)、纯右对齐无任何标记(扫长对话时容易漏)。

**代价**:① 等宽中英混排比无衬线难读,长提问会吃力;② 右对齐让每段起点不固定,快速纵向扫视时
不如左对齐的清单好找;③ 右侧边线很细,投影/低对比屏上可能看不见。

**复查条件**:如果出现"找不到自己刚说的话",先把右边线加粗到 2px 或加深到 `ink/70` ——
**不要**回填黑底;如果长提问读起来累,先把正文字号提到 13px,再考虑换成无衬线 + 2px 右边线。

## "卡在调用工具里"的根本原因:提示词比能力大

**症状**:在 Web 里让它读文件,答复是
`<tool_call>{"name": "shell", "arguments": {"command": "pwd && ls -la"}}</tool_call>` ——
一段**正文**,不是工具调用。没有工具块、没有执行、也没有后续,看着像卡死。

**复现**(真 key、无头浏览器、一次请求):`[resp] 200 /responses` 之后 5 秒内就"就绪",
答复正文就是上面那段标记 —— 不是网络卡住,也不是循环卡住。

**根因**:`SYSTEM_PROMPT` 写死了"你可以调用工具来读文件、写文件、列目录、执行 shell 命令",
但 Web 客户端调的是 `agent.run(text, settings, [], observe)` —— **工具集是空的**。请求里既然
没有 `tools`,模型只能在**正文**里模仿工具调用标记,客户端当然不认。

**修法**:提示词按本次 `run` 的工具集现拼(`systemPromptFor(toolNames)`):

| `tools` | 提示词里的行为段                                                                             |
| ------- | -------------------------------------------------------------------------------------------- |
| 非空    | "你可以调用这些工具:a、b…" + 原有规则                                                        |
| 空      | "⚠️ 本次运行没有任何工具可用" + 不许输出 `<tool_call>` / 不许声称执行过命令,拿不到就说拿不到 |

**验证**:同一条提问(真 key)重跑 —— 答复变成
"文件名是 `README.md`…但内容我读不了:本次运行我这边没有任何工具…"。单测 +2 条
(有工具/无工具时系统消息各断言一次),`pnpm test` 45 项全绿。

**代价**:提示词分成两套,改规则要同时改两处(用同一条 `PERSONA` + 分支拼接,已经尽量少重复);
另外 Web 端现在会**明确拒绝**需要工具的任务 —— 这是诚实,但用户可能期待它能干更多。

**复查条件**:一旦 Web 端有了自己的工具(浏览器内可跑的),把 `RULES_WITHOUT_TOOLS` 那条分支删掉;
如果哪天给 HTTP 加了超时/重试,才轮得到怀疑"真卡死"这一类症状。

## 删掉 `ApiConfig` 服务:密钥与端点并入 `LlmSettings`

**起因**:用户指出 `agent/src` 里不该有 `config` —— apiKey / baseUrl 属于 LLM 的设置。
原来的形状是"全局配置服务 + 按次行为参数":`ApiConfig`(密钥/端点)在 Layer 里固化,
`LlmSettings`(模型/档位)按次传。两套东西,两个读 env 的入口(`config.ts` / `settings.ts`)。

**改法**:只剩一份设置。

| 前                                                                  | 后                                                          |
| ------------------------------------------------------------------- | ----------------------------------------------------------- |
| `LlmSettings { model, thinking }`                                   | `LlmSettings { model, thinking, apiKey, baseUrl }`          |
| `ApiConfig` / `ApiConfigLive` / `ApiConfigShape` / `src/_domain.ts` | **全删**                                                    |
| `LlmDeps { api, client }`                                           | `LlmDeps { client }`                                        |
| `LlmLive: Layer<Llm, never, ApiConfig>`                             | `LlmLive: Layer<Llm, never, never>`(自带 `FetchHttpClient`) |
| 入口拼 `provide(ApiConfigLive)`                                     | 入口不用拼;`settings.ts` 四个 env 一次读成 `LlmSettings`    |
| Web 端按 key 重建 runtime                                           | 运行时**不持有配置**,一个就够;key 每次拼进 settings         |

另外新增 `BehaviorSettings = Pick<LlmSettings, "model" | "thinking">`:客户端只持久化这两项,
密钥仍然单独存(`archive001.web.key`),`DEFAULT_SETTINGS` 的类型就是它(密钥没有"缺省值")。
`DEFAULT_BASE_URL` 从 `src/_constants.ts` 移进 `llm/_constants.ts`,`src/_constants.ts` 只剩 env 名。

**收益**:① 同一进程可以用两个 key / 两个端点(测试就是这么打本地 mock 的,之前得靠 Layer 兜);
② `Llm` 变成"没有外部依赖"的服务,装配图短了一截;③ "设置"只有一处事实,不会出现
"模型能按次换、密钥只能全局换"这种不一致。

**验证**:`pnpm check` / `typecheck` / `build` / `test`(45)全绿;真 key 两条路都跑通 ——
Web(浏览器,密钥经 settings 进 Authorization)与 CLI(`THINKING=off pnpm cli "只回两个字:收到"` → `收到`)。

**代价**:① 每个调用点都要凑齐四项设置(客户端还行,脚本里略啰嗦);② `Redacted` 现在在客户端
代码里出现(use-agent 拼 settings 时),多了一个"别打印它"的心智负担;③ 历史文档里
`config.ts` 的叙述仍在 `docs/logs/2026-10-20.md`(历史不改写)。

**复查条件**:若哪天要支持"账号级默认值 + 单次覆盖",再引入一个 `defaultSettings` 参数,
而不是把 `ApiConfig` 请回来。

## 只有 apiKey 必填;env 读取从 SDK 挪到入口

**1. 三项变可选,缺省值收敛到一处**

| 项         | 必填?                            | 缺省                       |
| ---------- | -------------------------------- | -------------------------- |
| `apiKey`   | **必填**(没有"缺省密钥"这种东西) | —                          |
| `model`    | 可选                             | `deepseek-flash`           |
| `thinking` | 可选                             | **`high`**(原来 `low`)     |
| `baseUrl`  | 可选                             | `https://api.deepseek.com` |

补全只在 `LlmLive` 的边界做一次(`resolveSettings`),适配器签名收窄成 `ResolvedSettings` ——
"缺省值在哪赋值"从此只有一个答案。客户端持久化的那部分用 `BehaviorSettings`
(`Required<Pick<…, "model" | "thinking">>`),所以"存下来的设置"永远是有值的。

**2. SDK 不再读环境变量**

删掉 `packages/agent/src/settings.ts`(`llmSettingsFromEnv`),env → `LlmSettings` 下沉到入口:

| 层           | 文件                                                         |
| ------------ | ------------------------------------------------------------ |
| CLI          | `packages/agent/src/cli.ts`(约 25 行,含 `THINKING` 取值校验) |
| REPL / smoke | `packages/client/repl/src/_env.ts`(两个入口共用)             |

`index.ts` 不再导出任何读 env 的东西;顺手把 `ThinkingLevel` **作为值**导出,客户端拿它校验
`THINKING`(以前是用不了的只读类型)。

**验证**:`pnpm check` / `typecheck` / `test`(46,新增 1 条"只有 apiKey 必填 → 缺省值落位")全绿;
CLI 三种情况实测:正常 → `收到`;无 key → `缺少 DEEPSEEK_API_KEY(或 API_KEY)`、退出码 2;
`THINKING=ultra` → `THINKING 只能是 off | low | high | max,收到 "ultra"`、退出码 2。

**代价**:① env 读取的代码在 CLI 与 repl 各写了一份(约 25 行重复),想改 env 名要改两处
—— 这是把"读 env"从 SDK 赶出去的必然代价,换来的是 SDK 纯粹(调用方给什么就用什么);
② `thinking` 缺省从 `low` 改成 `high`,老用户会觉得"默认变贵、变慢"(但这也正是不写 `THINKING` 时的合理默认)。

**复查条件**:若第二份 env 读取开始漂移(比如 CLI 支持了 `THINKING=medium` 而客户端没有),
就把它抽成一个**独立的小包/子路径**(如 `@archive001/env`),而不是塞回 SDK 的 `index.ts`。

## 环境变量只留密钥

**一句话**:env 里只读 `DEEPSEEK_API_KEY`(兜底 `API_KEY`)。`model` / `thinking` / `base_url`
**一律不读环境变量** —— 它们是显式的参数,不是环境。

| 从哪来   | 读到什么                                    |
| -------- | ------------------------------------------- |
| 环境变量 | 只有密钥(机密才适合放 env)                  |
| 命令行   | CLI:`--model` / `--thinking` / `--base-url` |
| 代码     | 客户端直接给 `settings`                     |

**改动**

- `packages/agent/src/cli.ts` 重写参数解析:新增 `--model` / `--thinking` / `--base-url`,
  缺值时报用法错(`--model 需要一个值`),`--thinking` 用 SDK 导出的 `ThinkingLevel` 校验;
  环境变量只剩 key 一项。USAGE 也改了:env 那段只剩一行,行为参数挪到选项里。
- `packages/client/repl/src/_env.ts`:`llmSettingsFromEnv` → **`apiKeyFromEnv`**(只返回 key),
  repl 与 smoke 各自拼 `{ apiKey, ... }`。
- `scripts/smoke.ts`:档位改成**命令行参数**(`pnpm smoke max`),不再读 `THINKING`。
- `_constants.ts`(agent 与 repl 两份)删掉 `ENV_MODEL` / `ENV_THINKING` / `ENV_BASE_URL`。

**验证**:CLI 四种情况实测 —— 正常 → `收到`;`THINKING=max MODEL=… node src/cli.ts …`(旧 env)
→ 照旧用缺省跑通(说明确实不再读);`--thinking off` → 跑通;`--model`(缺值)→
`--model 需要一个值`;`--thinking ultra` → `--thinking 只能是 off | low | high | max,收到 "ultra"`。
`pnpm smoke`(缺省 high)真 key 跑通两轮工具对话;`pnpm check` / `typecheck` / `test`(46)全绿。

**代价**:① CLI 的参数解析从 3 行涨到 ~40 行(值得:它现在能自解释);② REPL 没能顺手加 flag,
所以 REPL 只能用缺省模型 / 档位 —— 要换得改 `main.ts`;③ 老脚本里 `THINKING=… pnpm smoke` 会**静默失效**
(不再报错,只是用缺省),这是"少读一项 env"的代价,已在 README / AGENTS 里写明新写法。

**复查条件**:REPL 真的需要换档位时,给它加和 CLI 一样的 flag(共用一套解析),而**不要**把
`THINKING` 请回环境变量。

## CLI 从内核包里搬出来,成为 `packages/client/cli`

**起因**:`packages/agent/src/cli.ts` 一直躺在内核包里 —— 但它是个**客户端**(只依赖 SDK、
装配依赖图、读环境变量、决定怎么打印),和 repl / web 是同一类东西。它待在内核里,等于内核
"知道有一个命令行前端",违反"agent 不知道任何客户端存在"。

**改法**

| 前                                                             | 后                                                   |
| -------------------------------------------------------------- | ---------------------------------------------------- |
| `packages/agent/src/cli.ts`                                    | `packages/client/cli/src/main.ts`(`@archive001/cli`) |
| `packages/agent` 的 `bin` / `exports["./cli"]` / `scripts.cli` | 全删;内核只剩 `.` 与 `./builtin-tools` 两个导出      |
| 内核 `vite.config.ts` 打包两个入口                             | 只打 `src/index.ts`                                  |
| 内核 `src/_constants.ts`(env 名)                               | 搬到 `client/cli/src/_constants.ts`                  |
| `pnpm cli` → `pnpm --filter @archive001/agent cli`             | → `pnpm --filter @archive001/cli dev`                |

`bin` 也改名为 `archive001`(原来的 `archive001-agent` 是"内核的 CLI"那个时代的名字)。

**收益**:① 依赖方向干净了:内核没有入口程序,所有入口都在客户端;② 新客户端照着 cli 包抄即可
(`package.json` / `tsconfig.json` / `vite.config.ts` 三件 + `src/main.ts`);③ 内核的 `dist` 只剩
`index.mjs`,发布面更小。

**验证**:`pnpm install --offline` 建立新包的 workspace 链接;`pnpm check`(83 文件)/ `typecheck`
(44 文件)/ `test`(46)/ `build`(agent 只出 `index.mjs`,cli 出 `main.mjs`)全绿;
`pnpm cli --help`、`pnpm cli --thinking off "…"` → `收到`、产物 `node dist/main.mjs --thinking off "…"` → `收到`
三条路都实测过。

**代价**:① 包数从 6 变 7,`pnpm -r` 相关命令慢一点点(可忽略);② `bin` 改名会让旧脚本里的
`archive001-agent` 失效(目前没有这样的脚本);③ 内核与 CLI 的 env 名现在各有一份常量
(本来就各读各的,不算新重复)。

**复查条件**:若以后出现第二个"一次性 / 脚本用"的客户端(比如给 CI 的 `--json` 专用版),
应该**复用** `@archive001/cli` 的参数解析,而不是再复制一份 main.ts。

## Web 客户端接上本地宿主:能读文件、能跑命令,密钥不进浏览器

按 A 方案落地(`docs/drafts/web-local-host.md` → [`designs/client/web/host.md`](../designs/client/web/host.md)

- [`decisions/0006-web-local-host.md`](../decisions/0006-web-local-host.md))。

| 之前                             | 现在                                                                     |
| -------------------------------- | ------------------------------------------------------------------------ |
| 浏览器直连 DeepSeek,`tools` 传空 | 浏览器 → **本地宿主(Node)** → DeepSeek                                   |
| 读不了文件、跑不了命令           | 内置四件套直接可用(`bash` / `read_file` / `write_file` / `list_dir`)     |
| 密钥明文在 `localStorage`        | 密钥只在宿主环境变量里;浏览器连"设置弹层"都没有了                        |
| `pnpm web` 起 Vite               | `pnpm web:host` 起宿主(Vite 中间件 + `/api/*`);`pnpm web` 只做纯前端迭代 |

**新增**:`src/host/main.ts`(HTTP + 前端托管 + `/api/{state,turn,reset}`,约 300 行,零框架)、
`src/host/_constants.ts`。**删掉**:`src/runtime.ts`(浏览器不再建运行时)、`controls.tsx` 里的
`SettingsDialog` / `TextField`、`.btn` / `.btn-ghost` 两条 CSS、`KEY_STORAGE_KEY`。

**协议**:`POST /api/turn` 回 `application/x-ndjson`,一行一个 JSON(`thinking` / `text` /
`tool_call` / `tool_result`),末行 `{_tag:"answer"}`;`use-agent.ts` 按行解析(留半行 buffer)。

**安全四条**(都实测过):只绑 `127.0.0.1`;`Host` 非回环 → 401;`Origin` 不同源 → 401;
无 cookie → 401。cookie 是启动时生成的一次性 token(`HttpOnly` + `SameSite=Strict`)。
`Host`/`Origin` 那两个 401 是用 `curl -H` 伪造验证的。

**cwd 与产物根分开**:工具的工作目录 = 启动宿主时的 `process.cwd()`(repo 根脚本
`web:host` 直接从仓库根跑),前端产物根 = `import.meta.dirname/../..` —— 不为 serve 页面把工具锁进包目录。

**验证**:`pnpm check` / `typecheck` / `test`(46)/ `build` 全绿;真 key 端到端:浏览器里问
"用 list_dir 看当前目录",宿主执行工具 → 界面出现工具块(列出仓库根文件)→ `答复` 总结;
无 key 时 `/api/turn` 回 503 且消息人话;prod 模式(`NODE_ENV=production`)serve `dist/` 的
index + `/assets/*.js` 都是 200。

**代价**:① `pnpm web` 单独跑会显示"连不上本地宿主"(纯前端迭代时没有工具,这是预期);
② 刷新 = 新会话靠挂载时 `POST /api/reset`,两个标签页会互相清历史;③ 宿主多一份 HTTP 与校验代码;
④ `bash` 无确认就能跑 —— 所以宿主只允许绑回环(写进 AGENTS 的"别做什么")。

**顺带发现**:`process-compose` 里 `finagent` 也用 `sops exec-env`,同样因为后台进程没有
`SOPS_AGE_KEY_FILE` 而起不来(状态 `Completed / 128`)。这次给 `archive001-web` 显式加了
`SOPS_AGE_KEY_FILE=/Users/zephyr/.config/sops/age/keys.txt` 才好;`finagent` 那条没动。
